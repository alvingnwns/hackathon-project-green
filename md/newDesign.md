# [SYSTEM FLOW & EXECUTION PIPELINE]
When I ask you to write code or design a system component, it must fit into this exact flow:

## Phase 1: Ingestion & Routing
1. The Frontend sends a request containing a user-uploaded photo to the FastAPI backend.
2. FastAPI receives the request and immediately passes the image to the **Gemini 3 Flash Preview** model for reasoning and metadata extraction.

## Phase 2: Split Routing (Data & Object)
3. **Data Branch (Red):** The reasoning data/info generated by Gemini is saved directly to the Supabase Database.
4. **Storage Branch (Blue):** The original raw image is uploaded to Supabase Object Storage.
5. **Linking:** Supabase Object Storage passes the object link/URL back to the Supabase Database to link the reasoning metadata with the image asset.

## Phase 3: Image Processing & Conditional Logic
6. The system pulls the image and evaluates a conditional state: **"Already Green?"** (Note: I will provide the specific parameters for what constitutes "Green" in the codebase).
   - **Condition Yes:** Execute logic to "Design new object / repair object and create the prompt."
   - **Condition No:** Execute logic to "Create object(s) prompt based on the image."

## Phase 4: Serverless 3D Generation Pipeline (Modal.com)
7. The synthesized prompt from Phase 3 is sent to **SD-XL 1.0**, hosted on Modal.com serverless infrastructure.
8. SD-XL 1.0 generates a refined 2D image.
9. This new image is automatically piped into the **Stable Fast 3D (SF3D)** model, which is also running on Modal.com.
10. SF3D generates the final 3D model in `.glb` format.

## Phase 5: Storage & Rendering
11. The generated `.glb` model is exported and saved back into Supabase Object Storage.
12. The Supabase Database is updated with the `.glb` object link.
13. The Frontend detects the update, fetches the `.glb` file, and successfully renders the 3D model for the user.
